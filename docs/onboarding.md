# 第一次進入專案

照順序做。**先摸已經在跑的東西，再讀要改的東西；設計規格最後才讀。**

1. 讀 `docs/product/product-overview.md` 的 §2「照見，不是問倒」，**只讀這一節**
   不先懂這句，後面所有取捨都會看起來像多餘的龜毛。
2. `docker compose up`，實際走一次對話，有問題先問AI讓它帶你跑一次
   手感優先於閱讀。http://localhost:5173 註冊後驗證頁會顯示本機驗證連結；開一門課、建一個活動，
   再用另一個帳號選課，走一次單人活動，最能體會「照見」的流程。
3. 讀 `backend/tests/invariants/`
   測試是規格的可執行版，比實作短，而且不會過期。
4. 讀 `backend/app/modules/solo_activity/attempt_machine.py` 與 `backend/app/modules/llm_runtime/policy.py`
   系統的心臟。讀完就懂流程怎麼推進。
5. 讀自己那條線對應的範本檔案（見 `AGENTS.md` 的範本索引）
6. 讀設計規格的相關章節
   到這裡才讀得懂它在描述什麼。

## 你的 AI 不會自動知道這些規則

本專案的規則寫在 `AGENTS.md`。有些工具讀 `CLAUDE.md`、有些讀 `.cursor/rules/`、
有些什麼都不讀需要你手動貼。**請自己確認你的工具真的讀到了。**

## 第一件任務

刻意挑「照著範本做一次」的小工作。第一個 PR 的目的不是產出，
是走完一次分支 → PR → CI → review → merge。

## 一件會讓你以為是 bug 的事

導師回覆是否來自真的 LLM，取決於教室擁有者或開課老師有沒有設定 provider profile：
沒有設定時，教室改用固定內容完成，單人活動則會提示老師還沒設定 AI。

## 卡住的地方請補回這份文件

第一次體驗結束時，如果可以請把你卡住的地方也補一段進來。你們的意見是這份文件最可靠的回饋來源。
